Plugin Development

Create powerful extensions for Vantis Media Player using WebAssembly (WASM).

Overview

Vantis Media Player uses a WASM-based plugin system that allows you to:

  • Extend functionality with custom features
  • Run code in a secure sandbox
  • Access host functions for media control
  • Support hot-reload for development
  • Distribute plugins via the marketplace

Quick Start

Step 1: Create Plugin Project

cargo new --lib my-plugin
cd my-plugin

Step 2: Configure Cargo.toml

[package]
name = "my-plugin"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
wasm-bindgen = "0.2"

Step 3: Implement Plugin

use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn plugin_init() -> String {
    "My Plugin initialized".to_string()
}

#[wasm_bindgen]
pub fn plugin_tick() {
    // Called every frame
}

#[wasm_bindgen]
pub fn plugin_shutdown() {
    // Cleanup
}

Step 4: Build WASM

cargo build --target wasm32-unknown-unknown --release
wasm-bindgen target/wasm32-unknown-unknown/release/my_plugin.wasm \
  --out-dir ./pkg

Step 5: Load Plugin

vantis plugins load ./pkg/my_plugin.wasm

Host Functions

Plugins can call host functions to interact with the player:

Logging

  • log(message: String) - Log a message
  • log_error(message: String) - Log an error
  • log_warn(message: String) - Log a warning

Media Control

  • play() - Start playback
  • pause() - Pause playback
  • stop() - Stop playback
  • seek(position: f64) - Seek to position (seconds)
  • set_volume(volume: f32) - Set volume (0.0-1.0)
  • set_mute(muted: bool) - Mute/unmute

State Query

  • get_position() -> f64 - Get current position (seconds)
  • get_duration() -> f64 - Get duration (seconds)
  • is_playing() -> bool - Check if playing
  • get_volume() -> f32 - Get volume

Utilities

  • get_config(key: String) -> String - Get config value
  • set_config(key: String, value: String) - Set config value
  • register_command(name: String, callback: i32) - Register custom command

Plugin Manifest

Create a plugin.toml manifest file:

[plugin]
name = "My Plugin"
version = "0.1.0"
author = "Your Name"
description = "A sample plugin"
category = "Utility"

[permissions]
# Required permissions
media_control = true
config_access = true
network = false

[dependencies]
# Plugin dependencies
required = []

Testing Plugins

Test your plugin during development:

# Load plugin
vantis plugins load ./pkg/my_plugin.wasm

# Enable hot-reload for development
vantis plugins enable-hot-reload my_plugin

# View plugin logs
vantis plugins logs my_plugin

# Unload plugin
vantis plugins unload my_plugin

Publishing to Marketplace

Share your plugin with the community:

Step 1: Prepare Plugin

  • Ensure plugin.toml is complete
  • Write comprehensive README.md
  • Add screenshots and examples
  • Test thoroughly

Step 2: Create Release

vantis plugins package ./my-plugin
# Creates my-plugin-0.1.0.vantisplugin

Step 3: Submit to Marketplace

vantis plugins publish my-plugin-0.1.0.vantisplugin
Note: Plugins run in a WASM sandbox for security. They have limited access to system resources and must declare required permissions in the manifest.
Warning: Be careful with performance in plugins. Avoid blocking operations in the tick() function as it's called every frame.
